## Project specifics

- Expo SDK 57 (`expo ~57.0.x`), React Native 0.86, React 19.2, TypeScript strict. Versioned docs: https://docs.expo.dev/versions/v57.0.0/
- npm project (`package-lock.json`), so use `npx`, not `bunx`.
- Verify with `npx tsc --noEmit`, `npx expo lint`, `npm test` (Jest, `jest-expo` preset). Single test: `npx jest src/domain/money`. Test files are `__tests__/*-test.ts(x)` next to the code.
- `app.json` enables `experiments.typedRoutes` (route hrefs are type-checked; types generated into `.expo/types` by `expo start`; `expo export` does not regenerate them. If tsc rejects a valid href with `/../…` entries in the error, the types are polluted on Windows: delete `.expo/types` and run `expo start` once on a free port) and `experiments.reactCompiler` (avoid manual `useMemo`/`useCallback` unless needed; use Reanimated shared values via `.get()`/`.set()`, not `.value`, or lint fails).
- Path aliases: `@/*` → `src/*`, `@/assets/*` → `assets/*`.
- Hermes on iOS has a partial `Intl`: `NumberFormat#formatToParts` is missing (Jest/Node has it, so tests won't catch it). Only use `Intl.NumberFormat#format`; derive anything else from formatted output (see `money.pattern.ts`).

## Architecture

The app is **Spendly**, a local-only expense tracker. Product/design spec: `context/IDENTITY.md`; build order and per-phase done criteria: `context/PHASES.md` (all built), then `context/PHASES-2.md` (the 10/10 plan: Phases 1–6 built in code, device checks pending; Phase 7 not started). Accessibility test matrix: `context/ACCESSIBILITY.md`. Read them before feature work; where the built app differs from IDENTITY.md, its status note at the top says so. IDENTITY.md says "bare RN, not Expo" — PHASES.md overrides this: stay on Expo (Expo Router, expo-sqlite, expo-haptics, …). No backend ever; Settings will have a disabled "Sync data" button only.

- **Routes** (`src/app/`): root `Stack` (`_layout.tsx`) wraps `GestureHandlerRootView` → app `ThemeProvider` → navigation theme; holds the `(tabs)` group (Add = `index`, Activity, Insights) and pushed screens `settings/` (+ `currency`, `export`), `categories/` (manage + `[id]` editor, `new` to add) and `expense/[id]`. Route files only re-export screens from `src/features/*/screens/`.
- **Theme** (`src/theme/`): `tokens.ts` holds all colors (light/dark), category colors, spacing, radius, the text scale (`Typography`) and the number font (`NumberFont`, `NumberSize`). `useTheme()` from `ThemeProvider.tsx` returns `{ colors, categoryColors, scheme, preference, setPreference }`. No hex colors or literal font sizes outside `theme/`: `theme/__tests__/tokensOnly-test.ts` fails on them, and `contrast-test.ts` checks every color pair against WCAG AA (text 4.5:1, icons/charts 3:1) in both themes, so changing a color means re-running it. The lime `accent` is only for the primary action and selected states (Save, selected `Button`s, the tab bar pill), always with `onAccent` content.
- **Motion** (`src/animation/`): `tokens.ts` (durations, stagger, springs, `ReducedTiming`), `transitions.ts` (`settleTo`, `useEnterTransition`, `useLayoutTransition` for items that move when neighbours change: slide, or cross-fade under reduced motion; `fade`: the shared opacity-only enter/exit preset; never redefine it locally) and `useReducedMotion()` — every animation must read these.
- **Money** (`src/domain/money/`): amounts are integer minor units; format with `formatMoney()` (currency exponent comes from `Intl`).
- **Domain** (`src/domain/`): `expense/` (types, `createExpense`/`updateExpense` validation, `parseExpense`, `ExpenseRepository`), `category/` (built-in categories with stable ids, `parseCategory`, `categoryDisplayName`, `CategoryRepository`), `insights/`, `export/` (CSV), `backup/`, `money/`. Repositories take a `() => Promise<Db>` and expose `subscribe()` so screens refresh after writes.
- **Storage** (`src/storage/`): one SQLite database (`database/connection.ts`, opened + migrated lazily on first use). Migrations in `database/migrations/` are append-only, versioned with `PRAGMA user_version`; never edit a shipped one. Timestamps are UTC ISO strings; local-day ranges come from `utils/dates.ts` and are compared as strings in SQL. Preferences (`storage/preferences/preferences.ts`: `usePreferences()` in components, `getPreferences()` outside React, `updatePreferences()` persists and re-renders every reader immediately; theme, reduced motion, haptics, currency and drag settings all read from it) and the unsaved Quick Add draft (`features/quick-add/state/draftStorage.ts`) live in `expo-sqlite/kv-store`, separate from the ledger. Preference write failures surface through `usePreferencesSaveError()` (Settings shows it).
- **Data safety** (PHASES-2 Phase 4): expenses are soft-deleted (`deleted_at`, migration v2). **Every read goes through the `live_expenses` view, never `FROM expenses`**; `remove` sets `deleted_at`, `restore` clears it, and rows deleted more than 30 days ago are purged when the database opens (`database/maintenance.ts`). Opening also runs `PRAGMA quick_check`; a damaged file is left untouched, `databaseHealth` is flagged and the root layout tells the user once. Undo is one persisted slot (`features/undo/state/undoStore.ts`: `saved` / `deleted` / `edited`, 5 s, survives a restart) used through `useUndo(kinds)`; offer it after a successful write. Write failures use `writeFailureMessage()` (`database/errors.ts`) so a full disk gets its own message. Backup (`domain/backup/`, `features/backup/backupActions.ts`): a versioned JSON file shared from Settings → Data; restore validates the whole file first (`parseBackup`, using `parseExpense` / `parseCategory`) and merges in one transaction, inserting only ids not already present.
- **Haptics**: only through `haptics` in `src/haptics/haptics.service.ts` (`tick` / `edge` / `select` / `success`); never import `expo-haptics` directly. Every haptic has a visible counterpart (see `context/ACCESSIBILITY.md`).
- **Activity / Edit** (`features/activity/`, `features/expense-details/`): Activity is an `Animated.FlatList` over `groupByDay()` items with fixed row heights (`getItemLayout`); only ids in `freshIds` (from `useExpenseSearch`) play an entering animation, so rows mounted by scrolling don't. Edit screen is route `src/app/expense/[id].tsx`; saving an edit or deleting offers Undo through `undoStore`, which Activity shows. `DetailsFields` is shared by Quick Add's details panel and the edit screen.
- **Insights / Export** (`domain/insights/`, `domain/export/csv.ts`): periods (week start from `deviceFirstWeekday()`) and day ranges are computed in JS and passed to SQL, so aggregation is exact across DST; never use SQLite `'localtime'`. Highlights (`domain/insights/highlights.ts`, pure and fully tested) turn the period plus a baseline into at most 3 sentences: the baseline is up to 8 earlier periods cut to the same elapsed days, only from after tracking began (`baselineWindows`); "usual" is their median; nothing is called unusual below 4 periods; a change needs ≥ 30% and `notableMinimumMinor(currency)`; changes rank above facts. The screen builds them (names and weekdays are UI concerns) and links category highlights/rows to Activity via a `categoryId` route param, applied once. Day states are `spent` / `zero` / `noData` (before the first expense or in the future), and must stay visually distinct. Charts are plain Views animated with Reanimated, one series in `colors.chart` (category colors fail CVD separation, so they only tint labelled icons). CSV goes to `Paths.cache` and the share sheet; user text is guarded against formula injection.
- **Language** (`src/i18n/`): every user-facing string is `t('namespace.key', params)` from `@/i18n`, defined in `locales/en/<namespace>.ts` and translated in `locales/ar/<namespace>.ts` (strictly typed: a missing Arabic key fails typecheck). One key per whole sentence with `{placeholders}`, never concatenated fragments; plurals are `{ one, other }` (Arabic: all six CLDR forms) called with `{ count }`, using our own rules in `plural.ts` (Hermes' Intl is unreliable). The language is read once at launch: Settings → Language (`system` / `en` / `ar`, own kv key, read by `src/i18n/index.ts` before anything else) or, for System, the phone's first supported language. Changing it calls `setLanguagePreference` (stores it and sets `I18nManager` RTL flags) then `reloadAppAsync()`, since module-level text and layout direction are fixed per run. `noHardcodedText-test` fails on literal text in components; `catalog-test` checks Arabic completeness and placeholders. Built-in category names are shown through `categoryDisplayName` / `useCategories()` (stored names stay English unless renamed). Right-to-left: RN mirrors `left`/`right` but not transforms, so anything positioned from measurements or `translateX` must handle `I18nManager.isRTL` (see MorphChip, AnimatedTabBar); numbers and the keypad force `direction: 'ltr'`. Test matrix: `context/ACCESSIBILITY.md`.
- **Accessibility**: text inside fixed-size controls gets `maxFontSizeMultiplier={FontScaleCap.*}` (theme tokens); free-flowing text is never capped. Important outcomes (save, delete, undo) call `AccessibilityInfo.announceForAccessibility`, since `accessibilityLiveRegion` is Android-only. Every drag has a button alternative.
- **Onboarding**: route `src/app/onboarding.tsx` (full-screen modal), pushed once from the tabs layout while `onboardingSeen` is false; Settings → About replays it. It reuses the real Quick Add components and saves nothing.
- **Release**: `eas.json` has a `preview` profile (internal distribution, Android APK) and `production`; build numbers are managed remotely by EAS. `npm run build:android` builds the preview APK; the user runs it (needs their Expo login). There is no Apple developer account: `npm run build:ios:unsigned` (profile `unsigned`, custom build `.eas/build/unsigned-ios.yml`) compiles without signing and packages `Payload/*.app` as an `.ipa` to sideload. App ids: `com.yassinebenzriouil.spendly`. Native changes (fonts, `expo-document-picker`, iOS `CFBundleLocalizations`) need a new build; JS-only changes don't. Quick Add saves record a `pendingExpenseId` in the draft first, so a kill between the DB write and the draft reset can't produce a duplicate on relaunch.
- **Keyboard**: `react-native-keyboard-controller` (`KeyboardProvider` in the root layout). Use its `KeyboardAvoidingView` / `KeyboardAwareScrollView`, not RN's or Reanimated's deprecated `useAnimatedKeyboard`.
- **Features** (`src/features/<name>/`): `screens/`, `components/`, `hooks/`, `state/`, `utils/`; shared hooks like `useCategories` live in `features/categories/`.
- **DB tests** run the real SQL against Node's built-in `node:sqlite` via `storage/database/testing/createTestDatabase.ts` (mock `expo-sqlite` in those tests). Jest runs with `TZ=America/New_York` (`jest.global-setup.js`) so DST boundaries are covered. `formatWithPattern()` (`money.pattern.ts`) formats money inside worklets where `Intl` isn't available.
- **Quick Add** (`src/features/quick-add/`): the state machine is a pure reducer (`state/quickAddReducer.ts`) — phase changes only through its events. The drag writes the displayed amount to a shared value every frame (`hooks/useAmountDrag.ts`) and commits to React state once on release. The mapping (`utils/dragMapping.ts`) is incremental and pure: `advanceDrag(state, dy, speed)` gives exactly one step per `pixelsPerStep` below `PRECISE_SPEED` and accelerates only with speed (`speedGain`); 0 and the maximum resist (`rubberBand`, `haptics.edge`). Its feel numbers are documented at the top of that file; tune those, not the code. The category morph is an overlay clone measured on the UI thread (`hooks/useCategoryMorph.ts` + `components/MorphChip`). Amount suggestions (`hooks/useAmountSuggestions.ts`, repository `amountSuggestions`) replace the drag hint in `AmountSurface`'s fixed-height `accessory` slot and load once per selected category, so they never reorder on screen. An untouched composer gets a time-of-day category via the reducer's guarded `categoryPreset` event (rule in `utils/smartDefault.ts`); a preset-only draft is never persisted. Dev builds log `[timing] expense logged in N ms` per save. Route `src/app/(tabs)/index.tsx` just re-exports the screen.
- **Side margins**: `Screen` pads every screen by `ScreenGutter`. Anything that scrolls, vertically or sideways (ScrollView, FlatList, KeyboardAwareScrollView, horizontal option rows), uses `EdgeToEdge` (`theme/tokens.ts`): `style={EdgeToEdge.scroll}` plus `EdgeToEdge.content` in `contentContainerStyle`. Otherwise horizontal rows stop short of the screen edge and lifted/scaled rows and shadows get cut at the gutter.
- **Spacing**: stacked cards (`ListRow`, anything with a filled background) are always separated by `ListGap` (`theme/tokens.ts`): `gap` on a View container, `ItemSeparatorComponent` on a FlatList (its `contentContainerStyle` has no gap). Rows that sit flat on the screen background (Activity) don't need it.
- **Native Switch**: RN's iOS `Switch` adds `alignSelf: 'flex-start'` to itself, so in a row it sits at the top unless wrapped in its own View (`ListRow`'s `accessory` slot already does this).
- **Reuse**: UI used in two or more places is a component in `src/components/` (or `features/<name>/components/` if feature-only), and repeated values (animation presets, spacing) are shared tokens; a helper used by one screen stays local to it.
- **Components** (`src/components/<Name>/index.tsx` + `styles.ts`): `Screen`, `Button`, `IconButton`, `Icon`, `ListRow` (settings/management row; its `accessory` slot centers controls), `OptionGroup` (one-of-n buttons, edge to edge), `TextField`, `Swatch`, `AnimatedNumber` (every amount and total: per-digit rolling digits in Space Grotesk, embedded via the expo-font plugin; `live` follows a shared value per frame, `hero` quiets symbol and decimals, `fit` shrinks to width; amounts inside sentences, buttons and captions stay plain `formatMoney` text), `MoneyTotals` (several currencies side by side), `EmptyState`, `AnimatedTabBar`, `ThemeFade` (fades light/dark switches), `ErrorBanner` (inline error: icon + message), `SortableList` (hold-and-drag reorder on the UI thread; Manage Categories pairs it with move up/down screen-reader actions). `Icon` maps stable keys to SF Symbols / Material Symbols via `expo-symbols`; add new icons to its map.

## Rule: everything is animated

Every visible change in the UI animates — no exceptions, including the ones that seem too small to bother with: press states, color/border/opacity changes, selection and disabled states, content appearing or disappearing, list inserts/removals, value and text changes, tab bar, tab switches, screen and sheet transitions, keyboard, toasts, errors, empty states. An instant visual state change is a bug.

- Use the tokens and helpers in `src/animation/` (`Duration`, `Springs`, `settleTo()`, `fade`, `useEnterTransition()`, `useLayoutTransition()`); don't invent ad-hoc timings.
- Reduced motion is not "no animation": drop movement/scale and replace with a short fade or color timing using `ReducedTiming` (`ReduceMotion.Never`, otherwise Reanimated skips it).
- Animate on the UI thread (Reanimated shared values), never by re-rendering React per frame.
- Tab bar: `src/components/AnimatedTabBar` (sliding pill, animated icon/label); tab content transitions use `animation: 'shift'` (`'fade'` under reduced motion) in `src/app/(tabs)/_layout.tsx`.

## Rule: device testing is done by the user

The user tests every change on their own phone. Don't try to launch simulators/emulators, run native builds (`expo run:*`, `eas build`) or drive the app to verify behavior. Verify with typecheck, lint, unit tests and `npx expo export` (bundling) only, then list what the user should check on device.
